## Why Gate5C exists
Previously, Business comparisons were calculated from `computeBusinessOptions()` but the app saved `business_config` and only its *headline* priced proposal_items; this is not immutable independent proof of KeepIT and UseIT prices. The original FIN02 backend correctly refused to award a compare proposal. Gate5A proved a separate selected-mode proposal can be awarded with source-checked pricing and recurring/temporary discounts, but created the frozen alternatives manually as fictional SQL inputs.

Gate5C tests the missing security and integrity seam, **with a trusted source of priced alternatives simulated inside PostgreSQL 17**. The software still does NOT have a real server-side price-catalog approval/freeze feature and the production wizard is NOT wired to Gate5C.

## What is NOT proven or implemented — release blockers
1. **True source authority and discount approval**: SQL LAB price book is filled by privileged fictional fixtures. Real system must calculate from trusted server `pricing_rules`, catalog version, approved commercial exceptions and *per-role discount limits*. No browser-provided prices, hashes, chosen option or `frozen` flag accepted as authority. **The current candidate does not enforce real approval matrices**.
2. **Persist real versioned priced alternatives**: the frontend still saves only a headline priced option. The new helper creates complete DISPLAY previews, but is NOT wired into CreateProposalDialog, nor is a proper signed-off server comparison/freeze API connected to mark Ready or lifecycle statuses. Decision required: freeze on Ready (recommended) vs a later authorized approval event. Source `proposal_items` lacks an independently stored immutable price-rule *version*; the SQL lab uses rule_version=1 solely for test fixtures. Real migration/RLS auditing needed.
3. **Immutability and server workflow**: the lab snapshots are immutable under normal DML with a trigger. Real storage/grants, disabled triggers/superuser exceptional access, conflict/retry of concurrent **freeze calls**, and version/source lock correctness must be tested on the full original TEST clone, not assumed solved from one transaction and replay.
4. **FIN01 integration**: Gate4D source-aligned atomic Business Draft save passed synthetic tests but is not wired to real UI/API; request-id retry and server discount authorization/role matrix remain #43.
5. **FIN03 official document binding**: #45/Gate5B database-ledger proof uses fictional bytes, not real DOCX/PDF upload, signed URLs, write-once storage or atomic DB/file recovery. An official customer-facing comparison DOCX/PDF must bind to the same TWO frozen alternatives, and the chosen proposal document must bind to selected option fingerprint; no existing document overwrite allowed. PR #32 remains separate Draft.
6. **QA01 real TEST**: no full authenticated, end-to-end no-manual-fix Thai Union run. Original TEST PGDMP/Auth/role/trigger faithful private restore #39 still pending. Historical Thai Union Won data must not be backfilled/rewritten silently.
7. **Release control**: no actual TEST/PROD SQL writes, no merge, deploy, Lovable/Work agent usage, production documents or outbound emails. PR #34 remains Draft and unmerged; Gate5C SQL is exclusively in `tests/sql` not `supabase/migrations`.
