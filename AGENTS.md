- Notification emails are dispatched only from the database notify() via pg_net to the shared app-email sender, gated by the private.notification_settings kill switch and its per-environment functions_base_url (null = never sends). Why: one central path with instant rollback and strict TEST/PROD separation.
- Renewal/proposal status changes go only through DB operations (validate_proposal, mark_proposal_sent, record_proposal_acceptance, close_renewal); guards are switchable warn/enforce via private.renewal_workflow_settings. Why: one auditable official close with instant rollback.
- Direct Sales (deals.sales_engine='new_business') is authorized only through the shared deal boundary public.deal_row_access (used by deals RLS and can_view_deal/can_manage_deal); capability comes from the 'sales' module via sales_capability(). Why: one boundary for deals and every child table, partners always excluded.
- Direct closing (Won / Award & Convert / licence from deal) is blocked by DB triggers until explicitly enabled. Why: server-side interlock independent of UI.
